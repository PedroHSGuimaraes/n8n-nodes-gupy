# Cobertura da API Gupy
Auditoria feita em 9 de novembro de 2026 (horário de São Paulo) sobre as páginas de referência em <https://developers.gupy.io/reference>.
O catálogo tem **179 operações** extraídas dos blocos OpenAPI dessas páginas. Cada linha abaixo liga a página de origem à operação do node e ao teste que confere método, caminho e autenticação.
Páginas sem bloco OpenAPI não viraram endpoint. O changelog da Gupy cita skills evaluations, mas essa rota não apareceu no índice de referência auditado e por isso não foi implementada.
## Ambiguidades
- `POST /webhooks` e `PUT /webhooks/{{webhookId}}` exigem `postBackUrl` na lista `required`, mas a propriedade publicada é `postbackUrl`. O node pede a URL no formulário e envia as duas chaves com o mesmo valor. Fonte: <https://developers.gupy.io/reference/createwebhook>.
- `application.pre-hiring-information-filled` está na página [About webhooks](https://developers.gupy.io/reference/webhooks) e não está no enum de `POST /webhooks`. O trigger pode filtrar o evento se ele chegar, mas não consegue registrá-lo.
- A página [Rate-Limiting](https://developers.gupy.io/reference/rate-limiting) descreve 500 requisições por minuto por IP no WAF, com checagem a cada 30 segundos sobre os 5 minutos anteriores, e resposta 429 com header `WAF: Rate-Limit`. O componente OpenAPI `X-RateLimit-Limit` diz "Request limit per hour". O node aplica só o limite de 500/minuto em `api.gupy.io` e não inventa um limite por hora.
- Admissão, educação, pathways e clima não publicam o mesmo número. O node não impõe 500/minuto nesses hosts. Em leitura, 429, 502, 504 e falha de rede são repetidos. Escrita não é repetida.
- Admin Global documenta Bearer em <https://developers.gupy.io/docs/authentication>. O OpenAPI também cita os esquemas `central-company-id` e `company-uuid` sem definição. O node envia só Bearer.
- User management descreve "Only requires Bearer token authentication", mas o objeto `securitySchemes` da página não veio preenchido. O node envia Bearer e marca o esquema ausente.
- Clima: o OpenAPI das operações não declara security. O guia pede `Authorization: [token]` sem a palavra Bearer. O node segue o guia.
- Educação usa o query `secret`. O OpenAPI não declara um header. O segredo não entra no corpo nem no header.
- `POST https://accounts.api.gupy.io/v1/token` está no guia de autenticação do Admin e não nas 179 operações. O node não chama esse endpoint. Cole o Bearer já gerado.
- Listas do Admin cujo schema da resposta veio vazio usam o exemplo publicado (`result.data` ou `data`, e `total` quando o exemplo não traz `totalPages`). Posições: <https://developers.gupy.io/reference/positionpubliccontroller_findpositions_v1>.
- Arrays de query sem `style` no OpenAPI saem como chaves repetidas, o padrão OpenAPI 3 form/explode. Se algum endpoint exigir vírgula, isso continua ambíguo.
- Objetos sem propriedades (`clientHeaders`, `customFields.value`, `metadata`, `jsonSchema`, `uiSchema`, `data` e o corpo de `users_create` quando o schema não descrevia chaves) viram pares chave/valor. Não há um JSON livre para montar.
- `departmentId`, `roleId` e `branchId` de admissão não usam a lista de R&S. A documentação não diz que os identificadores são os mesmos.
- A página de webhooks não documenta HMAC. O segredo opcional é o header `Authorization` enviado em `clientHeaders`, comparado de forma exata. Não é assinatura.
